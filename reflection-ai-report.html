Reflection & AI Usage Report

What we learned, how we used AI, and how we worked as a team.

Project reflection

Our goal was to build a website that solves a real problem. We noticed that many older people in Bahrain, including members of our own families, find smartphones and online services confusing, and are often targeted by scam messages. This led us to create TechEase, an educational website with simple, step-by-step guides. Choosing a real audience changed how we worked: every decision had to answer the question "Will this be easy for a 70-year-old to use?" This made us think about accessibility from the very beginning instead of adding it at the end.

We are proud that the website meets all of the requirements. It has seven connected pages, a consistent design using one shared stylesheet, a responsive Bootstrap layout and a registration form with JavaScript validation. We also added features we believe are genuinely useful, such as the text-size buttons that remember the user's choice, the phone practice simulator where users rehearse sending a WhatsApp message with no risk, and the "Spot the Scam" quiz that lets them test themselves safely.

AI utilisation report

We used AI tools throughout the project, as required. Claude helped us plan the requirements, site map and user journey, suggested a style guide, checked our colour contrast and helped us write and explain parts of the HTML, CSS and JavaScript. ChatGPT helped us learn Bootstrap, CSS and JavaScript techniques not taught in our course, gave us a first draft of the scam tips, and created all of the photos on our pages. GitHub Copilot suggested code in VS Code for the phone simulator and the email check.

We did not accept AI output without checking it. For example, the AI contrast check showed that our first button colour failed accessibility standards, so we changed it. We also rewrote content in our own words, removed information we could not confirm, and tested every feature ourselves. Every use of AI is recorded in the AI documentation table on the Overview page, because being honest about AI use is part of working ethically.

Lessons learned

We learned that planning saves time. Creating the wireframes and style guide first meant the coding stage was much faster and the pages looked consistent. We also learned practical skills. For example, a name of three spaces first passed our form check, so we learned to use trim() before checking the length. We learned the Bootstrap grid and that one external CSS file updates every page. Finally, AI is a helpful assistant but not a replacement for our own judgement. It can make mistakes, so we must always review, test and understand the code and content it produces.

Team collaboration experience

We divided the work by pages and tasks (see the team roles on the Planning & Design page). We kept in touch through a WhatsApp group and held regular calls on Discord to plan and review our progress. We shared our files by sending ZIP folders in the chat. Our biggest challenge was agreeing on the project: we kept arguing about what the brief really required and which parts mattered most. We solved this by listing the pros and cons of each idea against the brief, and found that TechEase matched its focus on real-world value. A technical challenge was Bootstrap overriding our colours; we fixed it by loading our stylesheet after Bootstrap. Working as a team taught us the importance of clear deadlines and of checking each other's work. If we did this project again, we would use GitHub from the first day instead of sending ZIP files, agree on file names and a shared folder structure early, and test on real phones earlier.
